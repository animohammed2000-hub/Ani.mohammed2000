# إعداد وتشغيل Aani Social

هذه الخطوات تخص **نسخة Replit الحالية**. لا تُغيّر مشروع Aani أو Supabase الأصلي
ما لم تختَر المشروع الصحيح وتراجع التغييرات يدويًا.

## 1. إعداد واجهة Replit

في مشروع Replit الذي سيستضيف الواجهة، أضف إلى Secrets:

| الاسم | المكان | ملاحظات |
|---|---|---|
| `VITE_SUPABASE_URL` | Replit | عنوان مشروع Supabase |
| `VITE_SUPABASE_PUBLISHABLE_KEY` | Replit | المفتاح العام الحديث، إن كان متاحًا |
| `VITE_SUPABASE_ANON_KEY` | Replit | بديل متوافق مع إعدادات المشروع القديمة |
| `VITE_SUPABASE_STORAGE_BUCKET` | Replit | اختياري؛ الافتراضي `aani-media` |

استخدم واحدًا فقط من مفتاحي الواجهة العامة. هذه القيم متاحة للمتصفح بعد بناء
Vite؛ لا تضع فيها مفتاح Gemini أو مفتاح `service_role`.
إذا كانت قاعدة البيانات الحالية تستخدم حاوية اسمها `media`، عيّن
`VITE_SUPABASE_STORAGE_BUCKET=media` بدل نقل الملفات أو تغيير اسم الحاوية.

### النشر على رابط عام

رابط المعاينة ورابط النشر قد يكونان نطاقين مختلفين. أضف القيم الثلاث الخاصة
بـ Supabase إلى **Secrets الخاصة بالنشر** أيضًا، وليس إلى Secrets المعاينة فقط،
ثم أعد بناء/نشر الموقع بعد حفظها. يجب أن يكون النشر عامًا ويستخدم HTTPS؛ لا
ترسل رابط المحرر أو رابطًا محليًا للأصدقاء. إعداد Vite يعيد توجيه المسارات مثل
`/login` و`/signup` إلى التطبيق، لذا اترك إعادة كتابة المسارات إلى `index.html`
مفعّلة لدى أي مستضيف خارجي.

### روابط ومزوّد تسجيل الحساب

في لوحة Supabase افتح **Authentication > URL Configuration**، واجعل **Site URL**
عنوان الموقع المنشور النهائي، وأضف رابط النشر الفعلي إلى **Redirect URLs** (مثل
`https://example.replit.app/**`). أضف كل نطاق مخصص تستخدمه أيضًا، وأضف
`http://localhost:5173/**` للتطوير المحلي فقط. يجب أن يطابق النطاق الذي يفتحه
المستخدمون؛ التطبيق يوجّه رابط تفعيل البريد إلى النطاق المفتوح وقت التسجيل.

في **Authentication > Sign In / Providers** تأكد من تفعيل مزوّد **Email** والسماح
بإنشاء الحسابات. إذا كان تأكيد البريد مفعّلًا، لا يستطيع المستخدم تسجيل الدخول
قبل الضغط على رابط التفعيل. لاختبار التسجيل مع أشخاص حقيقيين، اضبط SMTP موثوقًا
في **Authentication > SMTP Settings** وتحقق من نطاق المرسل؛ لا تعتمد على خدمة
البريد التجريبية لإرسال رسائل الإنتاج.

قبل فتح التسجيل للجمهور، تأكد أن قاعدة البيانات نفسها تحتوي جداول التطبيق
وسياسات RLS ومشغّل `on_auth_user_created_profile` لإنشاء ملف المستخدم. ملف
`supabase/schema.sql` في هذه النسخة نموذج للمخطط وليس شيئًا يُشغّل تلقائيًا؛
قارنه بمخطط مشروعك وخذ نسخة احتياطية قبل تنفيذ أي SQL.

بعد النشر اختبر من نافذة خاصة على النطاق العام: افتح `/signup` مباشرة، أنشئ
حسابًا ببريد تملكه، فعّل البريد إن طُلب، ثم سجّل الدخول وافتح `/feed` وأعد تحميل
الصفحة. إن فشل التسجيل، راجع رسالة الخطأ في الصفحة وسجل **Authentication**
في Supabase؛ لا ترسل مفاتيح أو رموز جلسات للدعم.

## 2. إعداد Supabase وGemini

في لوحة Supabase للمشروع الصحيح، افتح إعدادات أسرار Edge Functions وأضف:

| الاسم | مطلوب؟ | القيمة |
|---|---:|---|
| `GEMINI_API_KEY` | نعم | مفتاح Google AI Studio؛ أدخله داخل Supabase فقط |
| `ALLOWED_ORIGINS` | نعم للمتصفح | أصل Replit للمعاينة وأصل النشر، مفصولان بفاصلة |
| `GEMINI_MODEL` | لا | الافتراضي `gemini-3.8-flash` |

أدخل الأصل فقط مثل `https://example.replit.app`، لا مسار صفحة ولا `/` أخير.
أضف أصل المعاينة الفعلي أيضًا إذا كان ثابتًا لديك. لا تستخدم `*`؛ CORS ليس
بديلًا عن المصادقة.

### قاعدة البيانات

`supabase/schema.sql` هو المخطط الأساسي الموجود في الأرشيف. أضيف ملف تكميلي
اختياري `supabase/migrations/20261025000000_social_features.sql` لجداول القصص
والمحفوظات وإعادة النشر والإشعارات وسياسات RLS. لم يُنفّذ أي SQL في هذه المهمة،
ولا تُشغّل واجهة Replit هذا الملف تلقائيًا.

تحتاج تفاعلات المنشورات الجديدة إلى تطبيق
`supabase/migrations/20261027000000_post_interactions_and_moderation.sql` على
قاعدة Supabase نفسها. يضيف الترحيل RPC للعدادات الدقيقة، وخيارات «مهتم/غير مهتم»،
والبلاغات، وسياسة تعديل المنشور لصاحبه فقط. راجع الترحيل ثم شغّله من SQL Editor أو
Supabase CLI قبل اختبار هذه الميزات؛ لن تعمل الجداول والعدادات الجديدة قبله.
إذا لم تكن جداول `bookmarks` و`reposts` موجودة بعد، طبّق ترحيل
`20261025000000_social_features.sql` أولًا.

قبل تطبيق الترحيل على قاعدة موجودة، قارن أسماء الجداول والأعمدة وسياسات RLS
الحالية وخذ نسخة احتياطية. لا تشغّله إذا كانت الجداول موجودة ببنية مختلفة دون
مراجعتها. سياسة «الأصدقاء المقربين» المقترحة تعني المتابعة المتبادلة؛ راجعها
إذا كان مشروعك يستخدم قائمة مستقلة.

لا تضف `SUPABASE_URL` أو مفاتيح الخدمة يدويًا إلى Secrets المستضافة؛ Supabase
يوفر قيم الاتصال ومفاتيح Supabase المناسبة داخل بيئة الدالة. الكود يتحقق من
جلسة المستخدم عبر Supabase Auth، بالإضافة إلى تفعيل `verify_jwt`.

## 3. نشر الدوال

هذه الخطوات تتطلب أن يكون المطور داخل نسخة المستودع المرتبطة بمشروع Supabase
الصحيح، وأن يكون Supabase CLI مسجل الدخول. لا تشارك رمز تسجيل الدخول أو مفاتيح
الخدمات في المحادثة.

1. قارن `supabase/config.toml` ومجلد `supabase/functions/` مع المستودع الأصلي.
2. تحقق من اسم مشروع Supabase في لوحة التحكم قبل ربط CLI.
3. انشر `gemini-chat` بعد إضافة الأسرار.
4. الدالة `ai-assistant` القديمة صارت تتطلب جلسة مستخدم أيضًا، لكنها تحافظ على
   رد النجاح `{ reply }` لعملائها السابقين. ستتوقف أي استدعاءات مجهولة بعد
   حمايتها؛ تحقق من مستهلكيها قبل النشر، أو أوقفها إذا لم تعد مستخدمة.

أوامر CLI، من جذر المستودع الأصلي بعد التحقق من المشروع:

```sh
supabase login
supabase link --project-ref <PROJECT_REF>
supabase functions deploy gemini-chat
```

لا تنفّذ ترحيل قاعدة البيانات ضمن خطوات نشر الدوال. ملف الترحيل اختياري ولم
يُطبّق على قاعدة حية.

## 4. تشغيل وفحص نسخة Replit

في مشروع هذه النسخة:

```sh
pnpm --filter @workspace/aani-social run typecheck
pnpm --filter @workspace/aani-social run typecheck:edge
pnpm --filter @workspace/aani-social run test:edge
PORT=5173 BASE_PATH=/ pnpm --filter @workspace/aani-social run build
```

شغّل معاينة `Aani Social` بعد إدخال إعدادات Supabase.
إذا كانت مفاتيح Replit غير موجودة، لا يمكن تسجيل الدخول أو اختبار استدعاء
الدالة؛ لا يعني ظهور صفحة الواجهة أن Gemini يعمل.

## 5. تشخيص الطلب من المعاينة

1. في أدوات المطور، تأكد أن طلب `POST .../functions/v1/gemini-chat` أُرسل.
2. طابق `x-request-id` من الطلب مع سجل Edge Function.
3. الترتيب المتوقع للسجلات:
   `request_started` → `auth_check_started` → `auth_check_finished` →
   `gemini_request_started` → `gemini_response_received` →
   `request_succeeded`.
4. `request_started` وحده يثبت وصول الطلب للدالة فقط، ولا يثبت استدعاء Gemini.
5. `authState: invalid` يعني جلسة منتهية أو غائبة؛ `unavailable` يعني تعذر
   اتصال الدالة بخدمة المصادقة.
6. `gemini_request_started` دون `gemini_response_received` يشير إلى مهلة أو
   انقطاع اتصال upstream.
7. `gemini_response_received` ثم `gemini_json_parse_failed` أو
   `gemini_empty_response` يحدد مشكلة تحليل الاستجابة.
8. إذا سجلت الدالة `request_succeeded` ولم يظهر الرد، افحص حالة HTTP وجسم JSON
   في المتصفح، ثم تأكد أن نسخة الواجهة المنشورة تستعمل العقد نفسه.

لا تسجل الرسائل أو مفاتيح الجلسة. إلغاء الطلب في المتصفح لا يضمن إلغاء عمل
الخادم أو Gemini بعد استلام الطلب.

للتشغيل المحلي، أضف `http://localhost:5173` إلى `ALLOWED_ORIGINS` في بيئة
Supabase المرحلية، إلى جانب أصول Replit التي ستختبرها.

## 6. التراجع

- تغييرات هذه النسخة معزولة عن المشروع الأصلي؛ يمكن الرجوع إلى أرشيف ZIP أو
  نقطة تحقق في هذا المشروع.
- لم تُطبّق تغييرات SQL. إذا قررت تطبيق ملف الترحيل لاحقًا، راجع سياسة القصص
  والجداول مسبقًا؛ لا تتراجع بحذف جداول مستخدمة أو سجلات قائمة.
- قبل نشر الدوال، احفظ نسخة من الدالة المنشورة الحالية. عند الحاجة أعد نشر
  النسخة السابقة من المستودع الأصلي بعد مراجعتها.
- لا تحذف دالة Supabase أو جدولًا أو سياسة RLS لمجرد أن النسخة لا تعرضها.
